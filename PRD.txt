# 학교 전자칠판용 화면 미러링 프로그램 PRD — PC 수신 방식

**문서 상태:** 개발 착수용 초안 v0.6 (2026-11-17, 최대 6대 분할 화면)
**제품 목표:** 안드로이드폰과 학생용 Windows 11 노트북의 화면과 소리를 교실의 노트북·데스크탑으로 전송하고, 해당 PC에 연결된 전자칠판과 스피커로 출력한다.
**기본 구성:** Android 송신 앱(APK) + 학생 노트북용 ‘화면 보내기’ 프로그램 + Windows PC 수신 프로그램(접속 서버 내장). **별도 서버나 클라우드 없이** 교내 네트워크 안에서 동작한다.

> **설계 핵심:** 전자칠판에 내장된 브라우저(Chromium)는 영상 수신에 사용하지 않는다. 따라서 전자칠판 브라우저의 버전이나 기능은 미러링 성공 여부에 영향을 주지 않는다. 전자칠판은 PC의 HDMI 출력을 표시하는 장치로만 취급한다.

### 변경 이력

| 버전 | 변경 내용 |
|---|---|
| v0.2 | 교실 PC는 Windows 11, 관리자 설치 권한 있음, HDMI 연결로 확정했다. 소리 전송을 MVP 필수로 올렸다. Windows 10을 지원 대상에서 제외했다. 알림 노출 방지(FR-14)와 PC 절전 방지(FR-15)를 추가했다. |
| v0.3 | **클라우드 서버를 쓰지 않고, 접속 서버를 교실 PC 수신 프로그램에 내장**하기로 했다. 이에 따라 휴대전화 데이터망(LTE/5G) 연결은 MVP에서 제외했다. **MVP는 Android만** 지원하고 APK 파일로 배포한다. iPhone은 후속 단계로 옮겼다. 로그인 없이 접속 코드만 사용한다. 대표 시험 기기 기준을 정했다. |

| v0.6 | **모둠 활동을 위해 최대 6대를 동시에 연결해 화면을 나눠 보여 준다**(FR-11 변경, FR-23~FR-26). 2대 이상이면 기본으로 모두 음소거하고 교사가 기기별로 소리를 켜고 끈다. Android 앱과 학생용 송신기 모두 해당된다. |

## 1. 제품 개요

### 1.1 해결할 문제

교사는 수업 중 휴대전화의 앱, 사진, 문서, 동영상 등을 전자칠판에 보여 주고 싶다. 그러나 전자칠판에 설치된 소프트웨어가 오래된 경우에는 전자칠판 자체를 수신기로 삼기 어렵고, 기존 무선 미러링 기능은 기기 조합이나 학교망 환경에 따라 동작이 일정하지 않다.

이 제품은 **교실 PC를 공통 수신기**로 사용해 이러한 차이를 흡수한다.

```text
                       학교 네트워크(Wi-Fi·유선)
안드로이드폰 ── 화면·소리 전송 ──▶ 교실 PC 수신 프로그램 ── HDMI ──▶ 전자칠판(화면·스피커)
                                 (접속 서버 내장)
```

PC와 전자칠판은 이미 HDMI 등으로 연결되어 있다. **PC에서 전자칠판으로 보내는 구간은 Windows의 화면 복제·확장 기능과 HDMI 오디오 출력**을 사용한다. 전자칠판에 별도의 무선 전송 기능을 구현하지 않는다.

### 1.2 주요 사용자

- **교사:** 자신의 Android 휴대전화 화면과 소리를 수업 중 전자칠판에 출력한다.
- **학교 전산 담당자:** PC 수신 프로그램을 설치·업데이트하고, 휴대전화와 PC 사이의 교내망 통신이 가능한지 점검한다.
- **학교 관리자:** 사용 정책과 개인정보 처리 기준을 정한다.

## 2. 범위와 설계 전제

| 구분 | 내용 |
|---|---|
| MVP에 포함 | Android 화면 및 기기 소리 송신, 학생 노트북(Windows 11) 화면 및 시스템 소리 송신, Windows 11 PC 수신, 수신 프로그램에 내장된 접속 서버, 접속 코드·QR 페어링, 수신 승인, 화면 표시·종료, APK 파일 배포 |
| 후속 검토 | iPhone 송신 앱(Apple 개발자 계정과 배포 방식 결정 필요), 휴대전화 데이터망(LTE/5G)에서의 연결(외부 중계 서버 필요), macOS 수신기, 여러 교사의 발표 순서 관리 |
| MVP에서 제외 | 전자칠판 Chromium을 통한 영상 수신, 클라우드 서버, 사용자 로그인·계정, 전자칠판에서 휴대전화 원격 조작, 휴대전화 **마이크** 음성 전송, DRM 보호 화면·소리의 캡처 제한 우회, 영상 녹화, 공개 앱 스토어 등록 |

**확정된 현장 전제**

- 교실 PC는 대부분 Windows 11이며, 프로그램을 설치할 관리자 권한이 있다.
- PC와 전자칠판은 HDMI 등 유선으로 연결되어 있고, PC 화면이 전자칠판에 출력된다.
- **휴대전화와 교실 PC는 같은 학교 네트워크 안에 있어야 한다.** 서로 다른 VLAN이라면 두 VLAN 사이의 통신이 학교망에서 허용되어야 한다(6.2절).
- 학교는 외부 서버 사용을 허용하지만, MVP는 운영 부담과 비용을 없애기 위해 외부 서버를 사용하지 않는다.

## 3. 지원 환경 정책

아래 버전은 **초기 개발 목표**다. 구형 기기까지의 실제 지원 범위는 실기기 시험 후 확정한다.

| 구성 요소 | MVP 목표 | 구형 환경 대응 |
|---|---|---|
| Android 송신 앱 | Android 8.0 이상(화면). **소리 전송은 Android 10 이상** | Android 8~9는 화면만 전송하고, 소리를 보낼 수 없다는 사실을 앱에서 안내한다. 성능이 낮은 기기에는 해상도·프레임률을 자동으로 낮춘다. Android 7 이하는 지원하지 않는다. |
| 학생 노트북 송신 프로그램 | **Windows 11** | 관리자 권한 없이 사용자 계정에 설치된다. 주 모니터 또는 학생이 고른 모니터 하나를 보낸다. |
| iPhone 송신 앱 | **MVP 범위가 아니다.** | 후속 단계에서 Apple 개발자 계정과 배포 방식(TestFlight, App Store 비공개 등록 등)을 정한 뒤 개발한다. |
| Windows 수신 프로그램 | **Windows 11** | Windows 10은 2025년 10월 일반 지원이 종료되어 MVP 지원 대상에서 제외한다. 일부 남은 Windows 10 PC는 동작 여부만 참고로 기록하고 지원을 보장하지 않는다. |
| macOS 수신 프로그램 | MVP 범위가 아니다. | 학교에서 Mac을 수신 PC로 사용한다면 별도 요구사항으로 추가한다. |
| 전자칠판 Chromium | **사용하지 않는다.** | 버전과 무관하게 PC의 HDMI 출력 장치로 취급한다. |

**화면 캡처:** Android의 `MediaProjection`을 기반으로 구현하며, **운영체제가 요구하는 사용자 동의·시작 절차를 따라야 한다.** Android 14 이상에서는 공유를 시작할 때마다 새 동의를 받아야 하며, 화면 캡처는 `mediaProjection` 유형의 포그라운드 서비스에서 실행해야 한다. [Android Developers — Media projection](https://developer.android.com/media/grow/media-projection)

**소리 캡처:** `AudioPlaybackCaptureConfiguration`(Android 10 이상)을 MediaProjection 동의와 함께 사용한다. 미디어·게임 등 일부 용도의 소리만 캡처된다. 통화 음성은 캡처되지 않으며, 앱이 소리 캡처를 거부하도록 설정했다면 그 앱의 소리는 전송되지 않는다. [Android Developers — Capture audio playback](https://developer.android.com/media/platform/av-capture)

## 4. 사용자 사용 흐름

1. 교사는 교실 PC에서 **수신 프로그램**을 실행한다. 프로그램은 전자칠판에 접속용 QR 코드와 짧은 코드를 표시한다.
2. 교사는 휴대전화 앱에서 QR 코드를 스캔하거나 코드를 입력한다. QR 코드에는 PC의 교내망 주소와 일회용 접속 정보가 들어 있다.
3. PC에는 연결을 요청한 기기의 이름이 표시된다. 교사가 PC(또는 전자칠판 터치)에서 해당 요청을 승인한다.
4. 휴대전화 앱은 알림이 칠판에 노출되지 않도록 **방해 금지 모드 사용을 안내**한다(FR-14).
5. 교사는 휴대전화에 표시되는 **운영체제의 화면 공유 동의 절차**를 완료한다.
6. PC 수신 프로그램이 화면을 표시하고 소리를 PC의 기본 출력 장치(전자칠판 스피커)로 재생한다. 교사는 해당 창을 전자칠판에 전체 화면으로 띄운다.
7. 교사는 휴대전화 또는 PC에서 공유를 종료한다. 프로그램은 연결 종료 상태를 양쪽에 표시한다.

교실 PC가 전자칠판에 **복제 화면**으로 연결되어 있다면 전체 화면 창을 PC에 띄우는 것만으로 칠판에도 표시된다. **확장 화면**으로 연결되어 있다면 수신 프로그램에서 출력할 모니터를 선택할 수 있어야 한다. 소리 출력 장치도 프로그램 안에서 바꿀 수 있어야 한다.

## 5. 기능 요구사항

우선순위 **P0은 MVP 필수**, **P1은 첫 출시 후 개선**, **P2는 별도 검토**를 뜻한다.

| ID | 우선순위 | 요구사항 | 수용 기준 |
|---|---|---|---|
| FR-01 | P0 | Windows 11 PC 수신 프로그램은 전자칠판 Chromium이나 외부 서버 없이 독립 실행되어야 한다. | 별도 브라우저를 열거나 인터넷에 연결하지 않아도 접속 코드를 표시하고 영상·소리를 수신한다. |
| FR-02 | P0 | Android 앱은 사용자의 동의를 받아 휴대전화 화면을 송신해야 한다. | 공유 시작·중지·권한 거부가 정상 처리되고, 중지 후 캡처 자원이 해제된다. 다른 앱으로 전환해도 공유가 이어진다. |
| FR-04 | P0 | QR 코드와 짧은 접속 코드로 PC와 휴대전화를 페어링해야 한다. | 만료·오입력·이미 종료된 코드로는 새 연결을 시작할 수 없다. 코드 오입력이 반복되면 일정 시간 시도를 제한한다. |
| FR-05 | P0 | PC 측 교사는 송신 요청을 승인하거나 거절할 수 있어야 한다. | 승인 전에는 요청 기기의 화면과 소리가 출력되지 않는다. |
| FR-06 | P0 | 같은 Wi-Fi와, 서로 통신이 허용된 다른 교내망(유선·VLAN)에서 연결되어야 한다. | 휴대전화가 PC의 접속 포트에 도달할 수 있는 시험망에서 연결된다. 도달할 수 없으면 원인(다른 네트워크, Wi-Fi 기기 간 통신 차단, 방화벽 등)을 추정해 표시한다. 휴대전화 데이터망(LTE/5G)에 연결된 경우 Wi-Fi로 전환하라고 안내한다. |
| FR-07 | P0 | PC 수신 프로그램은 전체 화면 표시, 출력 모니터 선택, 소리 출력 장치 선택을 지원해야 한다. | 복제·확장 디스플레이 환경에서 의도한 전자칠판 화면과 스피커로 출력된다. |
| FR-08 | P0 | 화면 회전·종횡비 변경에 대응해야 한다. | 화면 일부가 잘리지 않고 비율을 유지하며 표시된다. |
| FR-09 | P0 | 네트워크 또는 기기 성능이 부족하면 전송 품질을 조절해야 한다. | 자동 조절이 동작하고, 교사는 ‘안정성 우선/화질 우선’을 선택할 수 있다. 대역폭이 부족할 때는 영상 품질을 먼저 낮추고 소리 끊김을 최소화한다. |
| FR-10 | P0 | 연결 상태와 오류를 교사에게 이해 가능한 문장으로 안내해야 한다. | 권한 거부, 코드 만료, PC에 도달할 수 없음, 연결 끊김, 소리 미지원 기기를 구분해 표시한다. |
| FR-11 | P0 | 한 PC에 휴대전화·노트북을 섞어 **최대 6대**까지 동시에 연결해 표시한다. | 7번째 요청은 기존 공유를 끊지 않고 거절하며, 교사에게 알린다. 접속 코드는 빈자리가 있는 동안 계속 쓸 수 있고 5분마다 바뀐다. |
| FR-13 | P0 | 휴대전화에서 재생되는 기기 소리(동영상·앱 소리)를 PC로 전송해 전자칠판 스피커로 재생해야 한다. | Android 10 이상에서 소리가 영상과 함께 재생된다. 영상과 소리의 어긋남이 체감되지 않는다(8장 목표). PC와 휴대전화에서 각각 소리를 끄거나 음량을 조절할 수 있다. Android 8~9에서는 화면만 전송되며 그 사실을 안내한다. 마이크 음성은 전송하지 않는다. |
| FR-14 | P0 | 공유 중 개인 알림이 칠판에 노출되지 않도록 해야 한다. | 공유 시작 전 방해 금지 모드 사용을 안내하고, OS가 제공하는 경우(Android 14 이상) 단일 앱 공유를 선택할 수 있다. 알림 소리도 함께 전송될 수 있음을 안내한다. |
| FR-15 | P0 | 공유 중에는 PC가 절전·화면보호기·화면 꺼짐 상태로 전환되지 않아야 한다. | 45분 공유 동안 PC 화면이 꺼지지 않으며, 공유 종료 후에는 원래 전원 설정으로 돌아간다. |
| FR-16 | P0 | PC 수신 프로그램 설치 시 수신에 필요한 Windows 방화벽 허용 규칙을 자동으로 추가해야 한다. | 설치 직후 별도 설정 없이 휴대전화에서 접속할 수 있고, 삭제 시 규칙도 함께 제거된다. 허용 범위는 교내망에 해당하는 도메인·사설 네트워크 프로필로 제한하고 공용 네트워크는 제외한다. |

## 6. 기술 아키텍처

### 6.1 구성 요소

| 구성 요소 | 역할 |
|---|---|
| Android 송신 앱 | 화면·소리 캡처, 영상·음성 인코딩, 전송 품질 조절, 공유 시작·중지 |
| 학생 노트북 송신 프로그램 | 코드로 PC 찾기(UDP 탐색)·주소 직접 입력, 화면·시스템 소리 캡처, 영상(H.264)·음성 인코딩, 전송 품질 조절, 공유 시작·중지 |
| PC 수신 프로그램 | 접속 코드·QR 표시, **내장 접속 서버(신호 교환)**, 교사 승인, 영상·음성 수신·재생, 모니터·스피커 선택, 절전 방지, 진단 정보 표시 |

**외부 서버는 없다.** 수신 프로그램이 교내망에서 접속 요청을 직접 받는다. QR 코드에 PC의 교내망 주소·포트와 일회용 접속 정보를 담아, 휴대전화가 PC를 찾는 단계를 단순하게 만든다. 짧은 코드만 입력하는 경우를 위해 같은 네트워크 안에서 PC를 자동으로 찾는 기능(mDNS 등)을 보조 수단으로 검토한다.

**확정한 구현 기술 (v0.4)**

| 구분 | 선택 | 이유 |
|---|---|---|
| 전송 | TLS 위의 자체 프레임 형식(docs/protocol.md) | 중계 서버가 없어 WebRTC의 망 통과 기능이 필요 없고, Android 쪽 구현이 단순하다. PC 인증서 지문을 QR 코드에 담아 가로채기를 막는다. |
| 영상 | H.264(Android MediaCodec 하드웨어 인코딩) | 거의 모든 Android 기기와 Windows PC가 하드웨어로 처리한다. |
| 소리 | 48kHz 스테레오 PCM | 교내망에서는 대역폭(약 1.5Mbps)이 문제되지 않고 지연이 가장 짧다. |
| 학생 노트북 송신 프로그램 | Electron(화면 캡처 + WebCodecs H.264 인코딩, 시스템 소리 루프백) | 수신 프로그램과 코드를 함께 쓰고 설치 파일만 따로 만든다. 공유 중에는 자기 창을 캡처에서 제외한다. |
| PC 수신 프로그램 | Electron(WebCodecs 하드웨어 디코딩) | 디코딩·소리 장치 선택·전체 화면·모니터 선택을 기본 기능으로 처리한다. PC 안에서 독립 실행되며 전자칠판 Chromium과는 무관하다. |
| Android 앱 | Java, minSdk 26 | 외부 라이브러리는 QR 스캔(ZXing)만 사용한다. |

### 6.2 지원하는 네트워크 범위

| 사례 | MVP 지원 | 조건 |
|---|---|---|
| 휴대전화와 PC가 같은 Wi-Fi(같은 네트워크 대역) | 지원 | Wi-Fi에서 기기 간 통신 차단(AP 격리)이 꺼져 있어야 한다. |
| 휴대전화는 교사용 Wi-Fi, PC는 유선 교내망 | 조건부 지원 | 두 네트워크 사이의 통신이 학교망에서 허용되어야 한다. |
| 휴대전화와 PC가 서로 다른 교내 VLAN | 조건부 지원 | VLAN 사이 라우팅과 수신 포트 통신이 허용되어야 한다. |
| 휴대전화는 LTE/5G, PC는 교내망 | **지원하지 않음** | 학교망 바깥에서 교실 PC로 들어올 수 없다. 앱은 Wi-Fi로 전환하라고 안내한다. 필요하면 후속 단계에서 외부 중계 서버를 검토한다. |

전산 담당자에게 **필요한 통신 조건(포트, 프로토콜, Wi-Fi 기기 간 통신 허용 여부)**을 정리한 점검표를 제공한다.

### 6.3 오래된 기기 대응 원칙

- 초기 전송 설정은 보수적으로 시작하고, 사용 가능한 대역폭과 기기 성능에 따라 품질을 높인다.
- 목표 화질을 달성하지 못해도 곧바로 연결을 종료하지 않고, 읽을 수 있는 최소 품질을 탐색한다.
- 코덱은 휴대전화와 PC 수신기에서 실제로 공통 지원하는 조합으로 협상한다.
- 구형 기기에서 발생하는 발열, 배터리 소모, 인코더 오류는 기종별 지원 목록에 반영한다.
- **‘설치 가능’과 ‘45분 수업에 사용 가능’을 서로 다른 합격 기준**으로 관리한다.

## 7. 보안 및 개인정보 요구사항

1. 화면 공유는 휴대전화 사용자가 직접 시작하며, PC에서도 연결을 승인해야 한다.
2. **로그인·계정은 사용하지 않는다.** 접속은 PC 화면에 표시된 일회용 코드와 PC 측 승인으로만 허용한다.
3. 접속 코드는 짧은 유효기간을 가지며 세션 종료 시 폐기한다. 코드 무작위 대입을 막기 위해 시도 횟수를 제한한다.
4. 신호 교환과 영상·음성 전송은 암호화한다. 교내망 안에는 공인 인증서가 없으므로, QR 코드에 담긴 일회용 정보로 PC를 확인해 같은 망의 다른 기기가 중간에서 가로채지 못하게 한다.
5. **녹화 기능은 제공하지 않는다.** 화면·소리 데이터는 PC 밖으로 보내거나 저장하지 않는다. 외부 서버가 없으므로 어떤 데이터도 학교망 밖으로 전송하지 않는다.
6. 진단 로그는 교실 PC에만 저장한다. 로그에는 화면 내용, 소리, 사진, 학생의 개인정보를 남기지 않고, 보관 기간이 지나면 자동 삭제한다.
7. 교사는 휴대전화와 PC 어느 쪽에서든 공유를 즉시 종료할 수 있어야 한다.
8. 공유 중 개인 알림이 노출되지 않도록 방해 금지 모드 사용을 안내한다(FR-14).
9. 학교가 관리하는 PC에는 프로그램 설치·업데이트·삭제 방법을 제공한다. 전산 담당자가 여러 PC에 일괄 설치할 수 있도록 무인 설치(`/S`)를 지원하는 설치 파일을 제공한다.
10. APK는 고정된 서명 키로 서명하고, 배포 파일의 해시 값을 함께 제공해 변조 여부를 확인할 수 있게 한다. 서명 키는 분실되면 기존 앱 위에 업데이트할 수 없으므로 안전하게 보관한다.
11. 운영체제 또는 콘텐츠 제공자가 캡처를 제한한 화면·소리는 검게 보이거나 들리지 않을 수 있다. 제품은 그 제한을 우회하지 않는다.

## 8. 성능 목표와 출시 기준

다음 값은 **검증을 위한 초기 목표치**다. 학교망의 상태에 따라 출시 전 조정할 수 있으며, 모든 네트워크에서 보장하는 수치가 아니다.

| 항목 | 초기 목표 |
|---|---|
| 최초 영상 표시 | PC 승인과 휴대전화 OS 동의가 완료된 후 **10초 이내**를 목표로 한다. |
| 화면 지연 | 양호한 교내 네트워크에서 **0.5초 이내**를 목표로 한다. |
| 영상·소리 동기 | 영상과 소리의 시간 차이를 **±150ms 이내**로 유지하는 것을 목표로 한다. |
| 기본 전송 품질 | 지원 가능한 기기에서 **720p·15fps 이상**을 목표로 한다. 구형 기기에는 낮은 품질을 허용한다. |
| 수업 지속성 | 대표 기기·망 조합에서 **45분 연속 공유**를 시험한다. |
| 실패 안내 | 네트워크·권한·코드 오류 등 주요 실패 상황에서 교사가 다음 조치를 알 수 있어야 한다. |

> 외부 중계 없이 교내망에서 직접 연결하므로 v0.2보다 최초 표시·지연 목표를 강화했다.

**MVP 출시 판정:** 대표 시험 기기와 지정된 학교망 환경에서 45분 수업 시나리오를 완료하고, 공유 시작·종료, 소리 재생, 화면 출력 모니터 선택이 정상 동작해야 한다. 연결할 수 없는 망은 성공 사례로 집계하지 않고 제한 사항에 명시한다.

### 9.2 시험 영역

|---|---|

## 10. 개발 단계

1. **현장 조사:** 교실 PC 사양, 전자칠판의 HDMI 오디오 출력 여부, 교사용 Wi-Fi와 PC 유선망 사이의 통신 가능 여부, Wi-Fi 기기 간 통신 차단 여부, 교사들이 실제로 쓰는 휴대전화 기종을 확인한다.
2. **기술 검증 시제품:** Android에서 화면과 소리를 캡처해 Windows PC 프로그램으로 직접 보내고, 45분 연속 동작과 교내망 연결 가능 범위를 시험한다.
3. **MVP 개발:** 내장 접속 서버, 페어링, 수신 승인, 전체 화면·모니터·스피커 선택, 품질 조절, 알림 노출 안내, 절전 방지, 방화벽 규칙, 오류 안내, 설치 패키지(MSI·APK)를 구현한다.
4. **학교망 실증:** 실제 교실에서 같은 망과 다른 교내망의 연결 가능 여부를 확인하고, 전산 담당자용 점검표를 확정한다.
5. **시범 수업 및 출시:** 교사 사용성을 검증하고, 실측 결과를 바탕으로 지원 기기·네트워크 목록을 확정한다.
